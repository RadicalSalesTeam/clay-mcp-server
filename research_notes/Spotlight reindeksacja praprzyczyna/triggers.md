# Environmental / configuration root causes of a repeatedly broken or incomplete macOS Spotlight index (macOS 13–26)

Scope note: about 17 search and fetch calls. Primary sources were Howard Oakley (eclecticlight.co), Apple Support 102321, and vendor docs or communities (Microsoft, Dropbox, Google). Much of the evidence on third-party apps is anecdotal forum material, and it is flagged as such below.

## 1. Cloud storage: iCloud Drive "Optimize Mac Storage", evicted (dataless) files, File Provider apps (Dropbox, Google Drive, OneDrive)

### Takeaway
Cloud files that are evicted or online-only do not corrupt the index. They are designed to be omitted from content search, so search looks "incomplete" every time macOS evicts files. The fix is to keep the files local ("Keep Downloaded" or "Always keep on this device") or to accept that only names can be found. A real index failure is a different problem. It needs a different fix (re-index the CloudStorage path, or check exclusions).

### Cited Findings
- iCloud Drive files that have been evicted, and so made dataless, become inaccessible to Spotlight until they are downloaded again. The whole of iCloud Drive is searchable only if files are local at search time. — [Eclectic Light: Using and troubleshooting Spotlight in Sequoia](https://eclecticlight.co/2024/11/29/using-and-troubleshooting-spotlight-in-sequoia-summary/)
- Recommended fix: use the Finder contextual menu command **Keep Downloaded** on files or folders that must stay searchable. — [Eclectic Light, Sequoia summary](https://eclecticlight.co/2024/11/29/using-and-troubleshooting-spotlight-in-sequoia-summary/)
- Rationale: evicted files are omitted rather than downloaded, because there is no guarantee a download would succeed and it would hold up the search. — [Eclectic Light: Searching iCloud Drive with Spotlight](https://eclecticlight.co/2023/07/19/searching-icloud-drive-with-spotlight/) (via search snippet); context in [Are we ready for dataless files](https://eclecticlight.co/2023/08/06/last-week-on-my-mac-are-we-ready-for-dataless-files/) and [iCloud Drive switches to dataless files (mjtsai)](https://mjtsai.com/blog/2023/10/27/icloud-drive-switches-to-dataless-files/)
- Sources conflict on whether content indexed while a file was local survives eviction. One Eclectic Light snippet says files whose data was stored locally stay indexed and searchable after eviction. Another says files evicted under Optimise Mac Storage are lost from Spotlight search. — [Eclectic Light, Searching iCloud Drive with Spotlight](https://eclecticlight.co/2023/07/19/searching-icloud-drive-with-spotlight/) vs. [Eclectic Light, Sequoia summary](https://eclecticlight.co/2024/11/29/using-and-troubleshooting-spotlight-in-sequoia-summary/) (search-snippet level; unresolved)
- Microsoft (official): Finder can find OneDrive online-only files **by name but not by content**, because their contents aren't on the device. — [Microsoft Support](https://support.microsoft.com/office/529f6d53-e572-4922-a585-e7a318c135f0)
- OneDrive moved to Apple's File Provider in build 22.002 (Jan 2022). Files marked "Always Keep on This Device" can still be reclaimed by macOS when disk space is low. — [Microsoft Tech Community blog: Updates to Files On-Demand on macOS](https://techcommunity.microsoft.com/blog/onedriveblog/updates-to-files-on-demand-on-macos/3207503)
- OneDrive users report that only fully hydrated files are content-indexed and that Spotlight does not index OneDrive's cache folder. Some report Finder search fails for OneDrive folders they have not visited yet. (Anecdotal.) — [Tech Community Files On-Demand Q&A](https://techcommunity.microsoft.com/discussions/onedriveforbusiness/files-on-demand-for-macos-qa/3101140)
- Dropbox: after migrating to File Provider (`~/Library/CloudStorage`), many users said Spotlight stopped indexing Dropbox content, sometimes even after a re-index. Reported workarounds: keep files local (not online-only); enable every Spotlight category, then add the folder to the Privacy list and remove it again; search "This Mac". Some users say name matching works but content matching does not. (Anecdotal, 2021–2023.) — [Dropbox Forum: Dropbox not searchable in Monterey](https://www.dropboxforum.com/t5/Create-upload-and-share/Dropbox-is-not-searchable-in-Mac-OS-Monterey-12-0-1/m-p/570942); [Dropbox Forum: Spotlight doesn't link to files in Ventura](https://www.dropboxforum.com/discussions/101001016/spotlight-search-doesnt-link-to-files-in-dropbox-in-macos-13-ventura/633406/replies/633569)
- Google Drive for desktop: streamed files are generally not content-indexed. Spotlight covers only downloaded or mirrored files in File Provider mode, and Google points to its own Drive search for the full corpus. One user cites an "Enable Spotlight to search streaming files" preference (older client). (Community answers.) — [Google Cloud Community thread](https://www.googlecloudcommunity.com/gc/Workspace-Q-A/Mac-Spotlight-not-indexing-Google-Drive-files-in-desktop/m-p/467714)
- In Sequoia, Spotlight withholds results from Library folders except `/Library/Application Support`. — [Eclectic Light, Sequoia summary](https://eclecticlight.co/2024/11/29/using-and-troubleshooting-spotlight-in-sequoia-summary/)
- A MacRumors Sequoia (15.7.x) user saw `mds_stores` write over 1 TB in several days, only while the Mac was asleep and charging. Excluding iCloud-related content reduced the writes, which came back when the content was re-included. No root cause was confirmed, and the user finally erased and reinstalled. — [MacRumors: How to fix the Spotlight disk write issues](https://forums.macrumors.com/threads/how-to-fix-the-spotlight-disk-write-issues.2477410/)

### Inferences
- File Provider sync roots live under `~/Library/CloudStorage`. The Sequoia rule that withholds Library results (Application Support excepted) may explain some "Dropbox/Drive vanished from Spotlight" reports. This is not confirmed, because CloudStorage appears to be exempted in practice for downloaded files.
- Recognition test: if a missing file has a cloud-download badge or shows as online-only, and searching after opening it (hydrating it) finds it, the cause is eviction, not corruption. Do not rebuild the index.
- Permanent fix: pin critical folders locally (Keep Downloaded, Always Keep on This Device, mirror mode in Google Drive). Keep enough free space that macOS doesn't evict pinned OneDrive files. Use the provider's own search for cloud-only content.

### Gaps
- No Apple documentation was found that defines how Spotlight treats File Provider dataless files on macOS 15/26.
- I couldn't fully resolve whether content indexed earlier persists after eviction.
- No current (2025–2026) Dropbox or Google official KB on Spotlight was found.

## 2. External/network drives, APFS volumes, Time Machine backups and snapshots, unmounting during indexing, exclusions

### Takeaway
Each volume keeps its own index in `.Spotlight-V100`. External disks and especially Time Machine stores drive `mds_stores` overload. A forced eject or unmount during indexing leaves stale "ghost" entries. Hidden exclusion markers or Privacy-list entries silently disable a volume. The durable fix is to rebuild the Data volume with external disks disconnected, then reconnect and rebuild each disk one at a time. Never force-eject while indexing, and audit exclusions.

### Cited Findings
- Since Time Machine backups moved to APFS, `mds_stores` (rather than `mdworker`) is the more likely cause of hyperactivity. The procedure: Safe mode, then restart. If that fails, shut down, disconnect external disks (especially TM stores), rebuild the Data volume index, then reconnect disks one at a time and rebuild each. Oakley says upgrading to Ventura largely resolved the TM indexing problem. — [Eclectic Light: mds_stores and mdworker in trouble (2022)](https://eclecticlight.co/2022/12/08/spotlight-problems-mds_stores-and-mdworker-in-trouble/)
- A reader says Spotlight indexes Time Machine volumes and that this can't be excluded. Oakley says there's no reliable way to see whether progress is being made. — [Eclectic Light, Sequoia summary (comments)](https://eclecticlight.co/2024/11/29/using-and-troubleshooting-spotlight-in-sequoia-summary/)
- Indexing a newly mounted external volume, or any volume after a macOS upgrade, can take hours to days and can block unmounting. Fix: Finder force-eject then restart, or shut down, disconnect, and start up. Each volume must be indexed separately. — [Eclectic Light, Sequoia summary](https://eclecticlight.co/2024/11/29/using-and-troubleshooting-spotlight-in-sequoia-summary/)
- A reader reported that force-ejecting a disk with open files (or a Terminal session in it) left its index out of sync, with ghost entries for long-deleted files. Another reader's SuperDuper clone wouldn't index because an exclusion marker was copied with the drive. Another saw files vanish from search minutes after re-adding a drive. Oakley advised leaving it powered for days, and noted some RAW image formats lack reliable importers. — [Eclectic Light: When and how to rebuild Spotlight indexes (comments)](https://eclecticlight.co/2024/11/19/when-and-how-to-rebuild-spotlight-indexes/)
- Rebuilding the root volume reportedly didn't fix search for one reader. They suggest targeting `/System/Volumes/Data`, where the indexes live. — [same](https://eclecticlight.co/2024/11/19/when-and-how-to-rebuild-spotlight-indexes/)
- Exclusion mechanisms: a folder name ending in `.noindex`, a leading dot, or Spotlight Privacy "Search Privacy…" entries (not indexed). The separate "Search results" list still indexes but hides results. An empty `.metadata_never_index` file no longer works in recent macOS. — [Eclectic Light, Sequoia summary](https://eclecticlight.co/2024/11/29/using-and-troubleshooting-spotlight-in-sequoia-summary/)
- Contradictory anecdote: a user fixed an external volume stuck at "Indexing and searching disabled" (`mdutil -s`) by deleting a root `.metadata_never_index` file, then running `sudo mdutil -i on /Volumes/X`. Others found that `mdutil -i on` and the Privacy add/remove step didn't help. — [Apple Community: "Indexing and searching disabled" for external drive](https://discussions.apple.com/thread/250621397); [Apple Community thread 252453820](https://discussions.apple.com/thread/252453820)
- An undocumented `ExternalVolumesIgnore` key in `com.apple.SpotlightServer.plist` is said to make mds skip external volumes. Its source admits it is unverified. — [community wiki](https://d19zmavcjzsuj4.cloudfront.net/wiki/Disabling_Spotlight_indexing_on_external_volumes) (low reliability)
- SMB network shares are unlikely to be searchable by local Spotlight in Sequoia. Oakley knows of no reliable way to enable it. — [Eclectic Light, Sequoia summary](https://eclecticlight.co/2024/11/29/using-and-troubleshooting-spotlight-in-sequoia-summary/)
- A reader says Time Machine backups don't use Spotlight, so index damage shouldn't affect them. Oakley adds that backup errors alongside index errors may point to a failing disk. — [Eclectic Light, When and how to rebuild](https://eclecticlight.co/2024/11/19/when-and-how-to-rebuild-spotlight-indexes/)

### Inferences
- Laptops that are frequently undocked (external disks yanked or force-ejected while `mds` holds them) are a likely recurring source of stale or "corrupt" external indexes. The permanent fix is a habit: eject properly, and leave the disk connected and awake until indexing settles.
- Clone or backup tools that copy hidden root files can carry exclusion state to new volumes. Check `mdutil -s /Volumes/X` after cloning.

### Gaps
- I found no source specifically on APFS local snapshots (`com.apple.TimeMachine.*` snapshots) affecting the Data-volume index.
- No Apple documentation was found on the `.metadata_never_index` deprecation. Behavior on macOS 26 is unverified.

## 3. Third-party apps: antivirus/EDR, cleaners, backup tools, Spotlight importers (.mdimporter)

### Takeaway
The best-documented third-party trigger is a crashing importer or malformed file. One bad file or a buggy third-party `.mdimporter` crash-loops `mdworker`, and every forced rebuild fails again at the same file. Evidence that antivirus/EDR or cleaners cause recurring corruption is mostly anecdotal or comes from vendor-marketing sources. I found no primary vendor KB.

### Cited Findings
- A malformed file, or one with a wrong or missing extension, makes `mdworker` crash. The log "normally records repeated crashes and restarts", and several `mdworker` copies burn CPU. Fix: find and remove or rename the file. — [Eclectic Light 2022](https://eclecticlight.co/2022/12/08/spotlight-problems-mds_stores-and-mdworker-in-trouble/)
- Forced rebuilds often fail when logs show repeated `mdworker`/mdimporter failures on a specific file. Oakley says problems are too often tackled blindly by rebuilding. — [Eclectic Light (search summary of multiple posts)](https://eclecticlight.co/2023/06/22/what-to-do-when-spotlight-cant-find-it/)
- Third-party mdimporter plugins may be less reliable than the bundled ones. It's unknown whether macOS skips files that repeatedly crash an importer. Newer logs redact filenames unless privacy protection is removed, which makes the culprit file hard to find. — [Eclectic Light: When and how to rebuild](https://eclecticlight.co/2024/11/19/when-and-how-to-rebuild-spotlight-indexes/)
- Diagnostics: `mdimport -L` lists importers. `mdimport -t -d3 <file>` shows which importer handled a file and what it extracted. `mddiagnose -f <path>` runs full diagnostics. Updated importers don't always re-index existing files. — [Eclectic Light, Sequoia summary](https://eclecticlight.co/2024/11/29/using-and-troubleshooting-spotlight-in-sequoia-summary/)
- Oakley's free tools Mints and SpotTest check for delayed finds, custom-importer failures, and volumes that fail to index. — [Check and diagnose Spotlight problems with SpotTest 1.1](https://eclecticlight.co/2025/08/28/check-and-diagnose-spotlight-problems-with-spottest-1-1/); [Diagnose Spotlight local search problems (Nov 2025)](https://eclecticlight.co/2025/11/20/diagnose-spotlight-local-search-problems/)
- Antivirus: a third-party macOS Tahoe guide lists antivirus software that blocks Spotlight's file access as a cause. It is not a primary source. — [macos-tahoe.com rebuild guide](https://macos-tahoe.com/blog/spotlight-rebuild-guide-fix-search-not-working-2025/) (low reliability)
- Cleaners: CleanMyMac and OnyX both offer "rebuild Spotlight index" or maintenance-script features, and OnyX also deletes system caches. One commenter says a rebuild worked for only "a few hours to 1–2 days". — [CleanMyMac FAQ](https://cleanmymac.com/faq/spotlight-slow-indexing); [Jesse Squires: fixing macOS search bugs](https://www.jessesquires.com/blog/2021/03/09/fixing-macos-search-bugs/); [sir-apfelot.de](https://www.sir-apfelot.de/en/?p=23890)
- A MacRumors thread advises using `mdutil` rather than GUI cleanup apps, so you know what is changed. — [MacRumors disk write thread](https://forums.macrumors.com/threads/how-to-fix-the-spotlight-disk-write-issues.2477410/)

### Inferences
- Cleaners that routinely "rebuild Spotlight" or purge caches cause recurring incomplete-search episodes by design: each run starts a full re-index that takes hours or days. Disabling their scheduled Spotlight or maintenance tasks is a reasonable permanent step. This is inferred, not documented.
- EDR/AV with file-system interception could slow or block `mdworker` reads. The standard mitigation would be vendor exclusions for `mds`, `mds_stores`, `mdworker(_shared)` and `/System/Volumes/Data/.Spotlight-V100`. This is unverified, because no vendor document was found.
- Recognition: a crash loop of `mdworker`/`mdworker_shared` in Console, or crash reports in `~/Library/Logs/DiagnosticReports` naming an mdimporter, means a bad file or importer. The fix is to remove the importer or file, not to rebuild.

### Gaps
- I found no CrowdStrike, Sophos, Bitdefender, Jamf Protect or SentinelOne KB on Spotlight interference or exclusions.
- No primary documentation was found on what CleanMyMac or OnyX deletes during their Spotlight tasks.

## 4. mds/mdworker crashes, CPU, memory, disk space, sleep/shutdown, TCC/FDA, FileVault, MDM

### Takeaway
Spotlight maintenance runs at low QoS (background and idle priority) and depends on idle time. Macs that never idle-complete their maintenance, or that are interrupted mid-maintenance, can show stale or incomplete results, and "disrupting routine maintenance may affect search results". Oversized indexes (hundreds of GB) on nearly full disks are a documented failure mode. Apple names permission/ownership problems as the reason a re-index fails for certain items.

### Cited Findings
- New files are indexed within about 1 s, with text in the content index in about 7 s. Recent data goes into transient posting tables that are periodically merged into static tables. Deleted files are purged only at the next housekeeping pass. Startup logs show "journal reset and sync" and `coremanagedspotlightd` replaying journals. — [Eclectic Light: In the background: Spotlight indexing (Feb 2026)](https://eclecticlight.co/2026/02/10/in-the-background-spotlight-indexing/)
- Macs shut down daily do most indexing maintenance shortly after login. Macs left running should do it during light use. For long maintenance, let the Mac run without sleeping. "Disrupting Spotlight routine maintenance may affect search results." Forcing a full reindex is likely to take longer than letting maintenance complete. — [same](https://eclecticlight.co/2026/02/10/in-the-background-spotlight-indexing/)
- Oakley speculates in comments that the housekeeper may be "overenthusiastic" in discarding entries. This is a guess, not a finding. — [same](https://eclecticlight.co/2026/02/10/in-the-background-spotlight-indexing/)
- Apple: indexing runs at setup, after software updates, and as data changes, and can take hours or days. It finishes faster when the device is **idle, plugged in, and on Wi-Fi/Ethernet**. If an "unknown" or permissions error appears when adding a folder to the Privacy list, the user may lack ownership of some items. Apple names permission problems as a likely reason a reindex fails for certain files. — [Apple Support 102321: About Spotlight indexing and search results](https://support.apple.com/en-us/102321)
- Oversized index: on Sequoia (M3 Pro, 1 TB disk), about 500 GB of "hidden space" and "System data" turned out to be `/System/Volumes/Data/.Spotlight-V100`. Symptoms were busy `mds`/`mds_stores`, heavy disk writes and a nearly full disk. Fix: delete `.Spotlight-V100` from Recovery, exclude folders with millions of files (`node_modules`, temp and log folders) via Privacy, then run `sudo mdutil -E /`. The author did not confirm a root cause. — [dev.to: How to avoid Spotlight using hundreds of GBs](https://dev.to/vvo/how-to-avoid-spotlight-using-hundreds-of-gbs-and-rebuild-its-index-4kki)
- A similar report found `.Spotlight-V100` using 233 GB for a large-dataset user. — [blopig.com](https://www.blopig.com/blog/?p=13858) (search snippet)
- Corruption is visible in logs as a failed assertion stating that the store at `.Spotlight-V100` is corrupt and needs a rebuild. One user saw `mds_stores`/`mdworker` crash daily even after deleting and rebuilding the index. — [Apple Community 7602735](https://discussions.apple.com/thread/7602735); [Apple Community 255536685 (14.4 crash)](https://discussions.apple.com/thread/255536685)
- A rebuild has started when the log shows "Server IndexCreate". If it doesn't start, add the volume to the Privacy list, restart, then remove it. — [Eclectic Light 2022](https://eclecticlight.co/2022/12/08/spotlight-problems-mds_stores-and-mdworker-in-trouble/)
- Rebuild only when the index is known to be damaged; slow indexing alone is no reason. `mdutil -E` suffices, with no need for `-i off`. `mdutil -X` deletes the index directory, which isn't recreated until `-i on`. The menu-bar progress indicator is unreliable. — [Eclectic Light: When and how to rebuild](https://eclecticlight.co/2024/11/19/when-and-how-to-rebuild-spotlight-indexes/); [Sequoia summary](https://eclecticlight.co/2024/11/29/using-and-troubleshooting-spotlight-in-sequoia-summary/)
- Heavy reset sequence used for recurring Mail and Spotlight stalls (Nov 2025): `mdutil -ia off`, then `mdutil -Ea`, a **reboot** (stressed as required), wait, `mdutil -Xa`, `mdutil -ia on`. Check with `mdutil -sav`. The re-index took over 2 h, and the author says the problem recurs with no known trigger. — [fy.blackhats.net.au: macOS Mail App Stuck Indexing](https://fy.blackhats.net.au/blog/2025-11-25-macos-mail-app-indexing/)
- MDM: documented payloads cover `allowSpotlightInternetResults` (Restrictions) and a `com.apple.Spotlight` custom profile that enables or disables result **categories** (adapted from a third-party source and unverified). A category disabled by profile disappears from results. I found nothing about MDM restricting local indexing of volumes. — [Hexnode: Configure Spotlight settings via profiles](https://www.hexnode.com/mobile-device-management/help/configure-spotlight-settings-on-macs-using-configuration-profiles.md); [JumpCloud Spotlight Internet Results policy](https://jumpcloud.com/support/create-mac-spotlight-internet-results-policy); [ManageEngine macOS restrictions](https://www.manageengine.com/mobile-device-management/help/profile_management/mac/mdm_mac_restrictions.html)
- Disabled categories also break search. Dropbox users fixed missing results by re-enabling all Spotlight categories in settings, and Apple tells users to check that the missing content type is enabled. — [Dropbox Forum](https://www.dropboxforum.com/t5/Create-upload-and-share/Dropbox-is-not-searchable-in-Mac-OS-Monterey-12-0-1/m-p/570942); [Apple 102321](https://support.apple.com/en-us/102321)
- Core Spotlight (corespotlightd: app indexes such as Mail and Pages) is separate from per-volume Spotlight. Rebuilding a volume index is unlikely to fix Core Spotlight problems, and TCC can't grant access to it. — [Eclectic Light: Spotlight and Core Spotlight are different (Jul 2026)](https://eclecticlight.co/2026/07/04/spotlight-and-core-spotlight-are-different/); [Sequoia summary](https://eclecticlight.co/2024/11/29/using-and-troubleshooting-spotlight-in-sequoia-summary/)

### Inferences
- Laptops that sleep constantly and are rarely idle-on-power, and desktops forced off by hard power-off, may never let journal merges and housekeeping finish. This fits Apple's "idle, plugged in" guidance and Oakley's "disrupting maintenance" warning. A practical permanent fix is a periodic restart, plus overnight periods awake on AC (for example with Amphetamine or `caffeinate`) after big changes or upgrades. This is inferred and not proven to prevent corruption.
- Low free space plus an index that grows into hundreds of GB is a self-reinforcing failure. Keeping comfortable free space (Apple-agnostic advice: tens of GB) and excluding high-churn folders addresses both.
- Ownership or ACL damage, for example on volumes migrated between users or Macs, is Apple's own named cause of partial re-index. Check with Get Info, or Finder "Ignore ownership on this volume" for externals.

### Gaps
- I found no primary source tying FileVault directly to index corruption. The only link is that a locked or encrypted external volume can't be indexed until it is unlocked, and that is not sourced here.
- No source documents memory pressure as a cause. It is mentioned only in generic third-party mds_stores guides.
- No Apple statement was found on TCC or Full Disk Access affecting `mds`. It is system-privileged, and FDA appears relevant only to third-party search apps.

## 5. Very large file counts (developer folders, node_modules, mail) and Mail.app indexing

### Takeaway
Millions of small, constantly changing files (`node_modules`, build output, caches, logs, VMs, datasets) inflate the index and keep `mds_stores` and `mdworker` busy. They are the main configuration cause of oversized or lagging indexes. Fix permanently with a `.noindex` suffix or Privacy exclusions. Mail search now relies largely on Spotlight and Core Spotlight. Fix it with a Spotlight re-index and Envelope Index rebuild, then let it finish.

### Cited Findings
- Exclude folders with many non-searchable files, such as `node_modules` and temp or log folders with millions of files, to stop index bloat (about 500 GB case). — [dev.to](https://dev.to/vvo/how-to-avoid-spotlight-using-hundreds-of-gbs-and-rebuild-its-index-4kki)
- Appending `.noindex` to a folder name excludes it from indexing. This is the per-folder exclusion that survives Privacy-list resets. — [Eclectic Light, Sequoia summary](https://eclecticlight.co/2024/11/29/using-and-troubleshooting-spotlight-in-sequoia-summary/)
- A MacRumors user found that moving Krita project files back onto the internal SSD reproduced heavy `mds_stores` writes, and excluding them from Spotlight reduced the writes. — [MacRumors](https://forums.macrumors.com/threads/how-to-fix-the-spotlight-disk-write-issues.2477410/)
- Mail: "Mailbox → Rebuild barely helps" because much of Mail search moved to Spotlight and Core Spotlight (MacRumors, macOS 27-era thread). One Sequoia user saw Mail search recover within seconds of a Spotlight reindex. — [MacRumors: macOS 27 email search completely broken](https://forums.macrumors.com/threads/mac-os-27-email-search-completely-broken.2487460/); [Apple Community 256288562](https://discussions.apple.com/thread/256288562)
- To rebuild the Envelope Index, quit Mail and remove `Envelope Index`, `Envelope Index-shm` and `Envelope Index-wal` from `~/Library/Mail/V#/MailData` (V10 on Ventura and later). Mail rebuilds it on relaunch. After major updates, Spotlight can take hours to re-index mail. — [Macworld](https://www.macworld.com/article/214924/solve-mail-search-problems.html); [Canary Mail blog](https://canarymail.io/blog/mac-mail-search-not-working) (secondary)
- Core Spotlight keeps Mail message contents out of Finder search. — [Eclectic Light, Sequoia summary](https://eclecticlight.co/2024/11/29/using-and-troubleshooting-spotlight-in-sequoia-summary/)
- Content-indexing bug (not environmental, but it confounds diagnosis): text files beginning with certain letters, such as "LG" or "HPA", fail content indexing, from Ventura through Tahoe. — [Eclectic Light (search summary)](https://eclecticlight.co/tag/spotlight/page/2/)

### Inferences
- Developer Macs should name build and dependency folders with `.noindex`, or keep repos in an excluded parent folder. Big mail stores (hundreds of thousands of messages) inflate both the Envelope Index and Core Spotlight, and repeated rebuilds there take a long time.

### Gaps
- I found no quantitative Apple limit on files per index or index size.
- No authoritative source covers Mail's exact current split between the Envelope Index, Spotlight and Core Spotlight on macOS 26.
